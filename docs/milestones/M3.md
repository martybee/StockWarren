# M3 — Trade History & P&L Persistence

> Draft work order (Claude, 2026-08-19) — replace with the §4-template version when provided.

**Status:** ⏳ planned · **Depends on:** M2 (validated persistence patterns)

## Goal

One canonical, queryable record per completed trade — entry, exit, P&L, slippage,
which account/strategy, and which signals fired — so the Compare page, the ML
trainer (M4), and the strategy decision (M5) all read from the same truth.

## Why now

Trade evidence is currently scattered: append-only text audit logs, Alpaca's
order history, in-memory stats that die on restart, and an empty `slippage.csv`.
Every downstream milestone needs consolidated history; build it once trades start
completing.

## Scope

**In:**
- A per-account trade store (SQLite preferred; structured CSV acceptable if
  simpler) written at position close, joining: our order intent, Alpaca fill(s),
  computed P&L, slippage vs expected price, and the signal snapshot that
  triggered entry.
- Restart-safe `stats` (win rate, total P&L, drawdown) recomputed from the store,
  not accumulated in memory.
- Dashboard Overview/Risk "Performance" cards and trade history table read from it.
- Document the store's schema in `SCHEMA.md`.

**Out:** backfilling Alpaca history from before the store existed; analytics UI
beyond the existing cards (M7).

## Acceptance criteria

- [ ] A paper round-trip (entry → exit) produces exactly one record with non-null
      P&L and slippage fields.
- [ ] Restarting the process preserves win rate / total P&L on the dashboard.
- [ ] The record states which of the 7 indicators confirmed at entry.

## Risks & guardrails

- The audit log in `logs/trades/` stays append-only and untouched — the store is
  derived truth, the audit log remains the tamper-evident record.
