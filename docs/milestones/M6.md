## Goal

The bot survives crashes, reboots, and Mac sleep without hand-holding — and a
running process can never again silently be 88 days older than the code on disk.

## Why now

Session notes gotcha #1: a dashboard process ran stale code for 88 days.
Today's setup is hand-started (`--dash-only`, bots started by hand in the UI,
`caffeinate` pinned to a PID by hand). One power blip ends trading until someone
notices.

## Scope

**In:**
- Load the launchd supervisor (`setup/services/com.stockwarren.bot.plist`) with
  the user filled in; restart-on-crash with the existing backoff wrapper
  (`setup/supervisor.sh`) or launchd's `KeepAlive`.
- Fold `caffeinate -s` into the supervised launch so sleep-prevention is tied to
  the service, not a hand-run PID.
- **Staleness guard:** at startup, log and expose (`/api/status`) the git commit
  the process was started from + process start time; dashboard header shows a
  warning when disk HEAD ≠ running commit.
- **Crash-restart policy — DECIDED 2026-08-19** (CHART_PLAN §14 Decision 3, pasted
  verbatim below; this resolves the question that was parked here):

  > **Crash-restart policy (paper phase): auto-resume if clean, with a crash-loop
  > breaker.** On supervised restart, the bots resume trading only if
  > `KILL_SWITCH.lock` is absent AND all state files pass validation; **three or
  > more restarts within one hour trips the kill switch automatically** and the
  > process comes up dashboard-only. Rationale: on paper money, an unmanaged open
  > position is a more real risk than an unsupervised bot; the breaker caps the
  > crash→trade→crash loop. **This decision is explicitly reopened at engine M8** —
  > for live money the calculus flips toward human-click.
- Runbook section in `CLAUDE.md`: start/stop/status commands, where logs are,
  how to clear the kill switch.

**Out:** off-Mac deployment (Linux service exists but untested — separate effort),
uptime alerting beyond the existing `/api/health` hook.

## Live cutover drill (Marty + Claude, market closed)

1. `cp setup/services/com.stockwarren.bot.plist ~/Library/LaunchAgents/ && launchctl load ~/Library/LaunchAgents/com.stockwarren.bot.plist`
2. Verify: `/api/health` 200; log shows "Process build: commit …[supervised]";
   bots auto-resumed (clean state); caffeinate visible in `pmset -g assertions`.
3. `kill -9` the PID → back serving within 1 min (criterion 1).
4. Reboot the Mac, log in → dashboard up (criterion 2).
5. Optional breaker drill: `kill -9` three times inside an hour → kill switches
   trip, dashboard-only, `⚠` visible; then remove locks by hand and kickstart.

## Risks & guardrails

- Supervised restart must never bypass the kill switch: if `KILL_SWITCH.lock`
  exists, the process comes up serving the dashboard but trading stays halted.
