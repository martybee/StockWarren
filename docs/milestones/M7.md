# M7 — Real-Time Dashboard & Decision Log

> Draft work order (Claude, 2026-08-19) — replace with the §4-template version when provided.

**Status:** ⏳ planned · **Depends on:** M3 (history store), M6 (stable process worth streaming from)

## Goal

See the bot think without tailing `stockwarren.log`: per-symbol evaluation
results streamed to the UI as they happen, replacing the 5-second polling loop.

## Why now

Flask-SocketIO is already initialized server-side but the page never connects —
the plumbing is half-built. And the #1 operator question ("why didn't it trade
X?") currently requires grepping logs; the Scanner page only shows on-demand
scans, not the live tick-by-tick verdicts.

## Scope

**In:**
- Wire the SocketIO client into `dashboard.js`: push tick events (per-symbol
  signal strength, confirmations, ML verdict, risk verdict, final action) and
  account-level events (order placed/filled, stop moved, halt tripped).
- A **Decision Log** view (new nav-rail section or Scanner extension): rolling
  feed of "symbol → verdict → reason," filterable by account and symbol.
- Persist recent decisions (ring buffer or table in the M3 store) so a page
  refresh doesn't blank the feed; schema documented in `SCHEMA.md`.
- Polling remains as fallback when the socket disconnects (badge shows which
  mode the page is in — honest state, per the existing badge philosophy).

**Out:** charts/candlesticks, mobile layout work, multi-user auth (dashboard
stays localhost-only).

## Acceptance criteria

- [ ] With the market open, a symbol evaluation appears in the Decision Log
      within ~1 s of the tick, no manual refresh.
- [ ] Every no-trade verdict shows *which* gate stopped it (strength,
      confirmations, ML veto, risk rejection, data validation).
- [ ] Killing the socket drops the page back to polling with a visible indicator.

## Risks & guardrails

- Ten symbols × three accounts per tick is a chatty stream — throttle/batch
  events so the UI thread and the log store don't become the bottleneck.
