# M1 — Safety-Invariant Test Suite

## Goal

A `pytest` suite that pins down the seven constitution rules in code, so any future
change that weakens a rail fails loudly before it ever runs against a market.

## Why now

The repo has **no test suite** and the safety rules are the one thing that must
survive every refactor. Tests come before new features on principle: trust the
rails first.

## Scope

**In:**
- One test module per constitution rule, named after it (`test_one_way_stops.py`, …).
- One-way trailing stop can tighten, never loosen (`risk_manager.py:update_trailing_stop`).
- `approve_order()` rejects: oversize positions, breached daily/weekly loss limits,
  poor risk/reward (< 2.0), second position in a correlation group, > 1× leverage.
- Kill switch: `trip()` works, **no reset method exists**, presence of
  `data/KILL_SWITCH.lock` blocks new orders.
- `validate_market_data()` → NO TRADE on missing/stale/contradictory/malformed data.
- `validate_order_response()` → unrecognized response trips kill switch + halt.
- `compute_uncertainty_factor()` scales size to 0 below `MIN_SIZE_FACTOR`.
- All broker calls mocked — the suite runs offline, never touches Alpaca.

**Out:** UI tests, live-API integration tests, ML model quality tests (M4).

## Deliverables

- `tests/` package + `pytest` in `requirements.txt` (dev section) + a
  `Testing` section update in `CLAUDE.md` replacing "No test suite yet".

## Acceptance criteria

- [x] `pytest` passes locally with no network access. (86 tests, ~0.1 s, broker mocked.)
- [x] Every one of the 7 rules has at least one test that names it. (Rule 4 has two modules.)
- [x] Mutation check: hand-weaken any rule (e.g. let a stop loosen) → a test fails.
      (Verified twice: stop `>` → `!=` and Rule 7 floor removal both caught, then reverted.
      Note: the first stop-mutation SURVIVED the price-path tests — the
      externally-tightened-stop tests exist because of it. See SESSION_NOTES 2026-08-25.)

## Risks & guardrails

- Don't refactor engine code to make it testable in the same commit as behavior
  changes — test the code as it stands first, refactor after green.
