# M2 — Data Schema & Validation

## Goal

Turn `docs/SCHEMA.md` from documentation into enforcement: every JSON state file
is versioned, validated on load, and a corrupt file can never crash the bot or
make it trade on garbage.

## Why now

All state is hand-editable flat JSON. Today a malformed `scheduled_trades.json`
or `operator_overrides_*.json` produces undefined behavior. Constitution rule 5
(malformed data ⇒ NO TRADE) should extend to our *own* files, not just market data.

## Scope

**In:**
- Add `"schema_version": 1` to `scheduled_trades.json` and
  `operator_overrides_<account>.json`; loaders accept versionless files as v0 and
  upgrade them on next write.
- Validation on every load: unknown fields warned, wrong types rejected.
- Fail-closed behavior: invalid file → quarantine it (rename `.invalid-<date>`),
  fall back to the safe default (no scheduled trades / config-file limits), log
  loudly, keep running.
- Tests for each loader (extends the M1 suite).
- Update `SCHEMA.md` to match what shipped.

**Out:** migrating to SQLite (that's M3's call), schema'ing `company_profiles.json`
(cache — delete on mismatch is fine).

## Acceptance criteria

- [x] Truncate `scheduled_trades.json` mid-file → bot starts, trades nothing from
      the scheduler, logs the quarantine, dashboard still loads.
      (`test_truncated_file_quarantined_then_fresh_save`)
- [x] Hand-edit an override value above its `OVERRIDABLE` ceiling → clamped on load.
      (`test_above_ceiling_value_clamped_on_load`)
- [x] Round-trip: load → save produces schema-valid output with `schema_version`.
      (round-trip tests in `tests/test_m2_state_files.py`)
- [x] Also delivered per discrepancy-hour ruling: tz-aware scheduling (naive =
      America/New_York), DST fall-back/spring-forward + half-day fixtures, and
      creation-time rejection of unparseable `scheduled_time`. Mutation-checked:
      a no-op quarantine and a UTC-naive parse each fail named tests.

## Risks & guardrails

- Never auto-delete a quarantined file — rename and keep it for post-mortem.
