# M4 — ML Pipeline to First Trained Model

> Draft work order (Claude, 2026-08-19) — replace with the §4-template version when provided.

**Status:** ⏳ planned · **Depends on:** M3 (labeled samples come from the trade store)

## Goal

Get each account's Random Forest from "untrained, approves everything" to a
trained, evaluated filter — and make its judgment visible on the ML page.

## Why now

The design already retrains every 10 new samples once 50+ exist, but with zero
completed trades nothing has ever trained. Once the bots trade paper daily and M3
records outcomes, samples accumulate on their own; this milestone makes sure what
trains is measured, versioned, and honest.

## Scope

**In:**
- Feature/label definition written down: what goes into a sample (indicator
  values at entry, signal strength, …) and what counts as a positive label.
- Per-account training with held-out evaluation (precision, veto rate) logged on
  every retrain; metrics surfaced on the dashboard ML page next to
  Trained/Untrained and sample count.
- Model artifacts versioned in `data/models/<account>/` with timestamp + sample
  count in the filename; previous model kept for rollback.
- Guardrail stays structural: the ML filter can only **veto** a proposed signal,
  never originate or upsize a trade.

**Out:** new model families, hyperparameter search, cross-account model sharing
(alpha/beta/gamma stay independent — they're the experiment).

## Acceptance criteria

- [ ] First account reaches 50+ samples and flips to Trained on the dashboard.
- [ ] Each retrain logs evaluation metrics and writes a new versioned artifact.
- [ ] Deleting the model directory degrades gracefully to approve-all + warning.

## Risks & guardrails

- Small-sample overfitting is certain at N≈50; display veto rate so a model that
  vetoes everything (or nothing) is visibly suspect.
